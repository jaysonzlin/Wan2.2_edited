# 832×480 I2V Training Variant Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (\`- [ ]\`) syntax for tracking.

**Goal:** Add an isolated \`832×480\` Wan TI2V training entry point, configuration, and H200 launcher without changing the current \`1280×704\` workflow.

**Architecture:** \`train_i2v_832x480.py\` is a standalone copy of the existing trainer and calls the existing dataset class with an explicit \`(832, 480)\` expected frame size. Its YAML config targets a separate native-resolution dataset directory. A new Slurm script mirrors \`submit_lingbot.sh\` while using isolated names and paths.

**Tech Stack:** Python 3, PyTorch, Accelerate, PyYAML, unittest/pytest, Slurm shell scripts.

## Global Constraints

- Preserve \`train_i2v.py\`, \`configs/train/overfit_kubric_i2v.yaml\`, and \`submit_lingbot.sh\` unchanged.
- Require exactly 49 RGBA PNG frames per sample at native \`832×480\` pixels.
- Use \`training_dataset_832x480\` as the new config’s default data root.
- Retain every Lingbot launcher override except resolution-specific file and identity paths.
- Use \`outputs/i2v_832x480\` for the new run’s checkpoints and artifacts.
- Do not add a resizing/conversion workflow, change model architecture, or alter inference CLI size lists.
